# OCR：给扫描版 PDF 加可搜索文字层

扫描版 PDF 里每页都是一张图。所谓"OCR 格式的 PDF"，在 PDF 术语里就是
**图像原样保留 + 一层不可见的文字层**（和 ocrmypdf 的产物同一种东西）：
看上去还是扫描件，但能选中、能 Ctrl+F、能被文字提取器读到。
文字层是写给机器看的，所以它不影响原书的版式和图像。

## 先判断该不该做

```bash
<py> scripts/pdftool.py info "<书.pdf>"
```

只看 `文字层` 一行：

| 判定 | 要不要 OCR | 说明 |
|---|---|---|
| `scanned` | **要** | 一个字都抽不出来，只能靠看页面图 |
| `text-garbled` | **要** | 有字符但全是乱码（字体缺 ToUnicode 映射），等于没有 |
| `text-partial` | 看情况 | 正文页已有文字，只有图版页没有——通常不必整册 OCR |
| `text-rich` | **不要** | 已有可用文字层，OCR 只会白花时间 |

判断依据是"每页平均字符数 + 高频虚词命中率"。一条硬规则：**别对 text-rich 的书跑 OCR**，
几百页要跑十几分钟，而已有文字层比 OCR 质量更好。

## 怎么做

```bash
# 整册 OCR，产出可搜索 PDF + 整册页锚全文
<py> scripts/pdftool.py ocr "<书.pdf>" --out "<书_ocr.pdf>" --sidecar "<书.pages.txt>"

# 只做某一章（先用 outline/info 确定页范围；--offset 换算印刷页码）
<py> scripts/pdftool.py ocr "<书.pdf>" --pages 120-180 -o "<书_p120-180_ocr.pdf>"

# 先看会做哪些页、要多久，不动手
<py> scripts/pdftool.py ocr "<书.pdf>" --dry-run
```

进度会按页打印：`[  12/396]   3.0%  p.12  行 37`。中断了重跑即可——
`--existing auto`（默认）会跳过已经做好文字层的页。

## 参数怎么调

| 参数 | 默认 | 什么时候改 |
|---|---|---|
| `--dpi` | 300 | 大开本（页面本体就有 900pt 宽）用 200 就够；小字密集的注释本、影印缩小本用 400-600 |
| `--jobs` | CPU 核数/3（上限 6） | 内存紧张调小到 2；每进程约 0.5 GB |
| `--min-conf` | 0.5 | 模糊/发黄的旧扫描件把错字塞进文字层反而更糟——可升到 0.6；反之降到 0.3 多要一点召回 |
| `--existing` | auto | `force` 全部重做（已有文字层也会被抹掉重写）；`skip` 只做完全没文字的页 |
| `--pages` | 全书 | 只需要某几章时务必用，省时间 |

`--existing force` 与乱码页会**先抹掉旧文字层**（`apply_redactions`，只删文字、
保留图像与矢量线条）。不抹的话，正确文字会和乱码混在一起，检索结果里全是噪声。

## 速度与质量

实测（12 核 CPU，中国古建筑木作营造技术，982×1412pt 大开本扫描件）：

- 单页 300 dpi：检测+识别约 4-5 秒，`--jobs 4` 时整册 396 页约 7-10 分钟
- 平均置信度 0.98-0.99，正文段落几乎可以逐字读
- 产物体积：64.8 MB → 66.4 MB（多出来的是嵌入的中文字体和文字对象）

**PP-OCR 类模型（本工具默认）容易错的几处**，看到别惊讶：

- 形近字：`橡/様`、`券/卷`、`己/已/巳`、`曰/日`
- 表格里的数字与符号（`1`/`l`、`0`/`O`）——**表格数字不要信任 OCR**
- 竖排或旋转的文字（模型会尝试自动纠向，但混排页面会漏）
- 页边注释、小于正文一半字号的字

所以：**OCR 文字是阅读与检索的拐杖，不是权威转录文本。**
要引用具体措辞、尤其是数字和专有名词时，回原页面图核对一眼
（`pdftool.py render --pages N --dpi 300` 出图后用 Read 看）。

## 质量自检

产物会有一次"体检"：回读 3 个抽样页，打印每页可提取字符数与前 40 字。
想深入核对，拿同一页做两件事比较：

```bash
<py> scripts/pdftool.py text "<书_ocr.pdf>" --pages 40     # OCR 读到的字
<py> scripts/pdftool.py render "<原书.pdf>" --pages 40 --dpi 300   # 原书那一页的图
```

图和文字对不上（缺段、串行、整段丢失）就是没做好：多半是 `--dpi` 太低，
或该页有分栏/表格式排版，需要提高 dpi 重做那一页。

## 引擎

`--engine auto`（默认）按顺序挑第一个可用的：

| 引擎 | 安装 | 特点 |
|---|---|---|
| `rapidocr` | `pip install rapidocr onnxruntime pillow`（本 skill 已装） | 自带 PP-OCRv6 中文模型，离线可用，纯 pip，中文书首选 |
| `tesseract` | 装 Tesseract-OCR + `chi_sim` 语言包，再 `pip install pytesseract` | 拉丁文/英文更好；中文需另装语言包 |
| `ocrmypdf` | `pip install ocrmypdf` + Ghostscript | 整册流水线（自动纠偏、分栏、压缩），装了会更好 |

引擎都不可用时脚本会直接给出安装命令，不会静默失败。新装引擎后
`pdftool.py check` 能看到它已经可用。

## 关于文字层的技术细节（排查问题时会用到）

- 文字用 `render_mode=3`（不可见）写入，字体是 PyMuPDF 内置的
  `china-s`（Droid Sans Fallback，含中日韩汉字），字体引用名固定为 `ocr-cjk`
- 每行按 OCR 框的坐标与高度放置，并做水平缩放让文字宽度贴合原文字宽，
  这样搜索命中的高亮矩形落在真字上
- 页面带 `/Rotate` 时会先转换坐标，文字不会跑到页面外
- 正因为有 `ocr-cjk` 这个标记，`to-ai` 能认出"这页的文字是 OCR 来的"，
  从而关掉"按字号判标题"（OCR 的字号是估的，会把表格内容当成章节名）

## 装不了引擎的退路

- 只要文本不要 PDF：`--no-pdf --sidecar out.pages.txt`
- 只想让模型看图读：跳过 OCR，直接 `render` 出页面图交给视觉阅读
  （book-kb-builder 的视觉路线就是这么干的）
